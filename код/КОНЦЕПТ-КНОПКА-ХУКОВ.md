# Кнопка «взять хук» в панели: концепт и что уже готово

Владелец: «заведу это в панель нейронка постер, чтобы кнопкой генерить посты».
Ядро и данные готовы и проверены, осталась только обвязка: три ручки в API и форма в панели.
Делает главный чат (панель и сборка постов его зона), ютуб-ветка отдаёт готовое ядро.

## Задача, которую это решает

Один пост уходит в тикток, инстаграм, ютуб и ВК, а хуки к нему берут разные ветки. Вопрос
владельца был прямой: «на 1 фото те же самые хуки берутся, как ты узнаешь, какой он взял?».
Без общего места на превью попадает ровно та строка, что уже стоит подписью в тиктоке.

Два конфликта, которые обязана закрывать кнопка:

1. **Дословный дубль.** Одна фраза на картинке и в подписи: вторая точка контакта сгорает.
2. **Разнобой регистров.** Картинка обвиняет, подпись жалеет, зритель не понимает, что за ролик.

## Что уже готово и работает

| файл | что делает |
|---|---|
| `хуки-пул.json` | 156 хуков владельца на 19 шаблонов, у каждого постоянный номер `face-report-h01` |
| `регистр.cjs` | определяет регистр речи: «крик» или «пов». Проверен на 15 спорных строках |
| `хуки-ядро.cjs` | весь подбор: совместимость, регистр по роли, редкие хуки вперёд. Без базы и консоли |
| `хук.cjs` | консольная команда поверх ядра, пишет в реестр |
| `синк-хуков.cjs` | сверяет пул с файлами генерки, не возвращает вычеркнутое владельцем |
| таблица `hook_usage` | реестр: пост, номер хука, роль, площадка, ветка, время |
| `ХУКИ-КАК-БРАТЬ.md` | инструкция для веток |

**Ядро уже отдаёт всё, что нужно кнопке.** Обвязке остаётся только вызвать его и показать.

```js
const { ШАБЛОНЫ, ВСЕ, ПО_ID, РЕГИСТР, шаблонИзКлюча, выбрать } = require('./хуки-ядро.cjs');
const res = выбрать({ шаблон, занятыеВсюду, занятыеПлощадки, роль, площадка, частота });
// res.выбран = {id, т, шаблон}, res.запас = ещё три того же регистра
```

## Три ручки, которых не хватает

```
GET  /api/hooks/templates
     → [{ шаблон, всего, крик, пов }]  для выпадающего списка

GET  /api/hooks/post/:key
     → что уже взято по посту: [{ роль, площадка, номер, хук, ветка }]

POST /api/hooks/take   { post, template?, platform, role, branch? }
     → { номер, хук, регистр, запас[], неКонфликтуетС[] }
     шаблон необязателен: ядро достаёт его из имени файла, а если там нет, из номера
     уже взятого хука по этому посту
```

Тело `take` повторяет то, что делает `хук.cjs`: читает `hook_usage` по `post_key`, считает
частоту за 14 дней, зовёт `выбрать`, пишет строку с `ON CONFLICT (post_key, role, platform)
DO NOTHING`. Повторное нажатие кнопки той же роли и площадки обязано вернуть **уже выданный**
хук, а не новый: иначе оператор двойным кликом наберёт два разных.

## Форма в панели

Поля: пост (имя файла без расширения), площадка (tiktok / instagram / youtube / vk),
роль (подпись / кадр / превью / заголовок), кнопка «Взять хук».

Под кнопкой таблица «уже взято по этому посту», она же ответ на вопрос владельца.
Рядом с выданным хуком показать запасные с кнопкой «взять этот вместо».

## Правила, которые нельзя потерять при переносе

* **Регистр зависит от роли, а не только от шаблона.** На кадре и в подписи всегда «пов»:
  крик с восклицаниями читается там как реклама. В заголовке и превью ютуба наоборот «крик»:
  дневник не цепляет. Это правка главного чата от 25.08, она уже внутри ядра.
* **Один регистр держится в пределах площадки**, а не на весь пост: зритель не видит кадр
  тиктока и превью ютуба рядом.
* **Номера хуков постоянные.** Новые строки получают следующий свободный номер, старые никогда
  не перенумеровываются: на них ссылается реестр и имена файлов.
* **Вычеркнутое владельцем не возвращать.** Отсев лежит в `вычеркнутые-хуки.json`, 67 строк,
  синк их не вливает. Проверено: в пуле ютуба их нет ни одной.
* **Ёфикация.** При сравнении строк схлопывать ё в е, иначе «ребёнок» и «ребенок» считаются
  разными и в пул льются дубли (на этом уже споткнулись).

## Что осталось за ютуб-веткой

Заголовки и превью ютуба: правила в 11 каналах переписаны под пул, дедуп заголовков заведён,
обложка научилась двум регистрам и перестала ломать «10/10». Метка шаблона проставлена
598 роликам из 745, оставшиеся 147 закроются, когда генерка начнёт класть в имя файла
схему `модель.шаблон.сборка`.
