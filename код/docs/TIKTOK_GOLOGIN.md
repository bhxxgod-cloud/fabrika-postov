# TikTok-автопостер: адаптация Threads-через-GoLogin гайда

Практическое, честное руководство. Это НЕ «ещё одна платформа по накатанной» — TikTok жёстче Threads по трём осям (гео-блок заливки, капча, поведенческий фингерпринт). Но 80% нашей архитектуры переносится один-в-один. Разберём, что общего, что нового, и где грабли.

---

## 1. Что переносится из Threads-архитектуры БЕЗ изменений

Эти инварианты работают на TikTok ровно как на Threads — код почти дословно тот же:

- **GoLogin connect (`wss://`, не `https://`).** GOTCHA1 живёт: `https://` заставляет Playwright сходить на `/json/version` за discovery → 404 → коннект падает. Только `wss://cloudbrowser.gologin.com/connect?token=…&profile=…`. Функция `cloudConnectUrl` идентична.
- **Логин ОДИН раз руками в десктопном GoLogin.** Пароли нигде не храним, сессия в куках профиля. Единственный секрет в env — `GOLOGIN_API_TOKEN`. `profileId` — строка из БД.
- **Двухуровневая проверка сессии.** `checkSessionFast` (REST `GET /browser/{id}/cookies`, ищет непросроченный `sessionid`) + `checkSessionDeep` (облако-запуск, читаем DOM). GOTCHA3 — кука ВРЁТ, `dead→live` поднимаем ТОЛЬКО через DEEP. Машину состояний по-прежнему держит воркер, не этот файл.
- **Шедулер (в соседнем файле).** Крон раз в минуту, прайм-слоты по timezone аудитории (МСК 9/13/19/21), джиттер ±20мин, ночная тишина 02:00–07:00, мин-гэп 25мин по всей сети, один пост за тик, очередь `draft→approved→publishing→published/failed/skipped`, аренда `SELECT … FOR UPDATE SKIP LOCKED`.
- **Вармап (в соседнем файле).** Лёгкие фид-сессии каждые 5–8ч, скролл + чтение + 1–3 лайка на ОРГАНИКЕ (никогда на своих аккаунтах!), печать char-by-char. `warmup_at` в БД, не в памяти.
- **БД-схема.** `accounts` / `posts` — те же, что в гайде. Ничего TikTok-специфичного в схему добавлять не нужно, кроме, опционально, поля `proxy_country` для гео-префлайта.
- **GOTCHA9 (редакция токена).** Токен в connect-URL → чистим `token=…` из любого текста ошибки. На TikTok это КРИТИЧНЕЕ: ошибок (челленджи, таймауты) больше → поверхностей для утечки больше.
- **Дисциплина публикации (GOTCHA4–7).** Успех — только по реальному сигналу, ожидание — ДО клика, таймаут ≥45–60с, ретраи после клика ЗАПРЕЩЕНЫ.

## 2. Что ПРИНЦИПИАЛЬНО другое на TikTok

| Ось | Threads | TikTok |
|---|---|---|
| **Заливка контента** | картинка/текст, маленький буфер, `setInputFiles` «на ура» | ВИДЕО, часто >50MB → упирается в потолок Playwright remote-CDP (~50MB). Заливка идёт в скрытый `input[type=file]`, потом server-side транскод 30–60с+ |
| **Капча** | редко | штатное явление (rotate/slider/3D-object) на свежих аккаунтах, новом IP, первых заливках. НЕ решаем никогда |
| **Гео прокси** | косметика (язык UI) | ЖЁСТКИЙ БЛОКЕР: с RU egress-IP заливка невозможна с 2022г. Просмотр работает — upload нет |
| **Редактор описания** | обычный | DraftJS `contenteditable` — `fill()` не работает, только посимвольная печать; `#`/`@` открывают фокус-крадущий попап |
| **Приватность** | есть дефолт | часто НЕТ дефолта — без явного выбора `Post` остаётся disabled |
| **Поведенческий фингерпринт** | важен | важен ГОРАЗДО сильнее: ~40+ сигналов за сессию, вес траектории мыши и provenance навигации высокий |

Всё остальное (connect, сессия, редакция токена, паттерн ошибок-пауз) — общее.

## 3. TikTok-специфичные грабли (нумеровано, как таблица гайда)

**TT-1. RU egress-IP = заливка невозможна.** Не капча, не баг — жёсткий гео-гейт ByteDance с марта 2022. Префлайт: если `resolveProxyCountry(profileId) === 'RU'` → `GeoBlockedError`, даже не пытаемся заливать (лишние попытки = ещё и триггер бана). Рабочее гео для рунет-аудитории — **Казахстан** (Беларусь — ловушка, TikTok там ограничен с 2021).

**TT-2. Капчу НЕ решаем. Никогда.** Ни руками, ни солверами (SadCaptcha и т.п. — против ToS, стоит денег, ломается на ротации, сам по себе вектор бана). Детектим DOM челленджа → `CaptchaError` → аккаунт на паузу, зовём человека очистить в десктопном GoLogin. Тот же паттерн, что `SessionError`. Капчу проверяем в КАЖДОЙ фазе: загрузка страницы, обработка, ожидание Post-enabled, до и после печати описания.

**TT-3. `CaptchaError`/`SessionError` — НЕ ретраебельны.** Это тонкий момент: воркер по гайду ретраит pre-click фейлы до 3 раз. Но три подряд облако-запуска в один живой челлендж = документированный триггер эскалации soft→hard бана. Поэтому у этих ошибок `retryable=false` и `pauseAccount=true`. Воркер ОБЯЗАН на них ставить `paused_until` на несколько часов и не перевыдавать профиль.

**TT-4. Видео >~50MB рвёт remote-CDP.** Playwright base64-кодирует весь буфер в одно CDP-сообщение; на облачном (не co-located) браузере большие буферы рвут транспорт (Microsoft #34192, closed «not planned»). Держи транскод ≤~45MB (TikTok всё равно перекодирует у себя), либо для больших файлов подмени шаг заливки на `puppeteer-core` (он тянет >100MB). Модуль предупреждает в лог при превышении `REMOTE_CDP_UPLOAD_SOFT_LIMIT`.

**TT-5. `setInputFiles` с явным длинным таймаутом.** Дефолтный action-таймаут короткий; base64-раундтрип многомегабайтного видео по WebSocket долгий → `{ timeout: 120_000 }`. Это ОТДЕЛЬНО от GOTCHA6 (таймаут баннера).

**TT-6. Нет iframe на `/tiktokstudio/upload`.** Старый `/creator-center/upload` заворачивал форму в iframe (старые гайды делали `frame.switch()`). Новый TikTok Studio рендерит форму в top-документе. Работаем на верхнем уровне; в `findFileInput` оставлен defensive-фоллбэк в iframe на случай A/B-отката.

**TT-7. DraftJS-описание.** `fill()` часто ничего не делает (внутренний стейт пустой). Печатаем `pressSequentially` (заодно анти-бан). Обязательно ВЕРИФИЦИРУЕМ через `textContent`, что текст лёг. Если не лёг — ПЕРЕпечатываем (не `fill()`! машинная вставка = бот-почерк там, где мы и так подозрительны); не лёг дважды — честно падаем ДО клика.

**TT-8. `#`/`@` крадут фокус.** Автокомплит-попап перехватывает Enter/стрелки: Enter вставит тег вместо переноса. Печатаем токен → ждём попап → гасим `Escape`.

**TT-9. Приватность выставляем ЯВНО.** Без выбора `Post` не активируется. `setPrivacy` при отсутствии дропдауна НЕ глотает это тихо, а падает pre-click (retryable) — это ровно причина, по которой кнопка осталась disabled.

**TT-10. Post — ждём `enabled`, не `visible`.** Кнопка disabled, пока не докрутится upload+processing И не провалидируются поля. Ждём именно enabled (плюс эвристика: нет `disabled`-класса). Если так и не активировалась — БРОСАЕМ (не возвращаем disabled-локатор!), иначе клик по неактивной кнопке даёт ~30с actionability-таймаут ПОСЛЕ `postSubmitted=true` и ложный `maybePublished`.

**TT-11. Успех — только короткий пост-сабмитный сигнал.** Баннер «видео загружено» живёт 5–7с ИЛИ редирект на `/tiktokstudio/content`. НИКОГДА не по стоячему UI студии. Мы намеренно выкинули из `successBanner` широкие кандидаты (`a[href*="/video/"]`, голый `Posted`, кнопки `View profile/Manage posts`, диалог `Manage your posts`) — они живут на странице ДО клика и давали ложный успех. Плюс перед взводом ассертим, что сигнала успеха ещё НЕ видно (fail-closed).

**TT-12. Второй confirm-модал на части когорт.** «Are you sure you want to post?» — и на этих когортах РЕАЛЬНАЯ публикация на этом клике. `maybeConfirm` ждёт до ~8с, гонится с сигналом успеха, и НЕ глотает ошибку клика молча.

**TT-13. Ретрай после клика = дубль + бан.** «Repeated upload retry attempts» — именованный триггер ограничений TikTok. `postSubmitted=true` ставим ДО клика; любое падение после — `maybePublished`, проверяет человек.

## 4. Чек-лист запуска TikTok-аккаунта

1. **Прокси:** свой стики-мобильный (4G/CGNAT) IP из **Казахстана**, не ротирующийся, не шаренный между аккаунтами. Мобильный доверяется сильнее резидентного; дата-центр — верная дорога к shadow-limit.
2. **Фингерпринт:** дефолтный когерентный фингерпринт GoLogin на профиль. НЕ мешать вектора руками (canvas/WebGL/audio должны быть согласованы), не переиспользовать между аккаунтами. Часовой пояс/язык фингерпринта = страна прокси = заявленная страна аккаунта.
3. **Логин руками** в десктопном GoLogin → очистить любую логин-капчу → **Stop профиля** (GOTCHA2: куки синкаются в облако только на Stop) → только теперь автопостинг.
4. **Идентичность изолирована:** свой email/телефон, свой IP, свой фингерпринт на аккаунт.
5. **Гео-история:** аккаунт, созданный/живший ранее с RU IP, даже на KZ-egress может получить срезанный охват — держи гео-историю согласованной с самого начала.
6. **Вармап ~14 дней:** максимум 1 пост/день, лёгкие фид-сессии, лайки/комменты только на органике третьих лиц. Никаких лайков/комментов на своих аккаунтах (engagement pod палится мгновенно).
7. **Гео-префлайт включён:** подключить `resolveProxyCountry`, чтобы RU-профиль ловился до заливки.

## 5. Требования к видео (веб-загрузчик / TikTok Studio, 2026)

- **Контейнер:** MP4 (предпочтительно) или MOV. Ставь MP4.
- **Видео-кодек:** H.264 (AVC), Main profile, level 4.1+. HEVC принимается, но H.264 надёжнее.
- **Аудио:** AAC-LC, stereo, ≥128 kbps, 44.1 kHz.
- **Соотношение:** 9:16 вертикаль. 1:1/16:9 примутся, но летербоксятся и хуже заходят.
- **Разрешение:** 1080×1920.
- **FPS:** 30 (talking-head) или 60 (динамика). CFR, не VFR.
- **Битрейт:** ~5 Mbps для 1080p30, 8–10 Mbps для 1080p60, минимум ~2 Mbps.
- **Размер:** веб-лимит 4 ГБ, НО наш практический потолок — **~45MB из-за remote-CDP** (TT-4). Транскодь под это; TikTok всё равно перекодирует.
- **Длительность:** мин ~3с (для надёжности), макс 10 мин (дефолт) / 60 мин (для избранных аккаунтов).

Кодируй под спеку ДО заливки — TikTok транскодит быстрее и чище, `Post` активируется раньше, риск реджекта ниже.

## 6. Честная оговорка про капчу и охват

- **Капча будет.** Ненулевая частота — данность даже на тёплом, ручным-логином, чистом KZ-мобильном профиле. GoLogin Orbita чинит `navigator.webdriver`, но НЕ доказано, что он патчит CDP-утечку `Runtime.enable` (Playwright шлёт её на каждый фрейм; анти-бот-стеки её детектят). Значит — планируй ручной разбор капчи с первого дня, не строй пайплайн в расчёте на ноль челленджей.
- **Мы капчу не обходим и не решаем.** Это осознанный отказ: солверы против ToS и сами по себе вектор бана. Обнаружили → пауза → человек.
- **Охват — честно.** KZ-гео + русскоязычный контент реально достаёт ШИРОКУЮ русскоязычную аудиторию (СНГ + диаспора + VPN-пользователи РФ), НЕ «всю Россию» в чистом виде. Для максимального внутри-РФ охвата первичной площадкой честнее считать VK Клипы (обогнала TikTok по MAU в РФ), а TikTok — русскоязычным усилителем. YouTube Shorts в РФ деградирован (троттлинг с июля 2024).
- **Дубли контента.** Детект TikTok по ВИЗУАЛЬНО-АУДИО фингерпринту, не по метаданным. Уникальная подпись на аккаунт НЕОБХОДИМА, но НЕ достаточна — нужно структурно разное видео (footage/монтаж/аудио) на аккаунт, иначе всё, кроме первой копии, задавит.

## 7. Как ТОТ ЖЕ паттерн расширяется на Instagram / YouTube

Модуль намеренно узкий: `connect` + сессия + `publishVideo` + типизированные ошибки. Инфраструктура (шедулер/вармап/БД/алерты) инжектится. Это и есть точка расширения — новый постер = новый файл `*-poster.ts` с той же формой:

**Общее для всех платформ (переиспользуется как есть):**
- GoLogin connect (`wss://`), редакция токена, `disconnect`/`stopCloudSession`.
- Паттерн ошибок-пауз: `SessionError`/`CaptchaError`/`PublishError` (+ `GeoBlockedError` где есть гео-гейт).
- Двухуровневая сессия, дисциплина «успех только по реальному сигналу, ожидание до клика, без ретраев после клика».
- Пер-аккаунтный `makeRng(profileId)` и `humanClick`/`humanPause` — анти-бан переносится дословно.
- Шедулер/вармап/БД/аренда — те же соседние файлы.

**Что меняешь под платформу — ровно три вещи:**
1. **`SELECTORS`** — свой объект (мультиязычный, data-e2e/role/text вперёд, классы в фоллбэк). Проверять живьём.
2. **Флоу `publishVideo`** — порядок шагов и специфика редактора/приватности/успеха.
3. **Платформенные гейты** — гео-блок, лимиты размера, тип капчи.

**Instagram (Reels):**
- Редактор описания — свой (не DraftJS), но идея char-by-char + верификация та же.
- Успех — свой сигнал (шаринг-экран/редирект в профиль), не закрытие композера.
- Заливка видео — тот же remote-CDP ~50MB потолок → тот же транскод-под-45MB или puppeteer-side-channel.
- Гео-блока как у TikTok нет → `GeoBlockedError`/префлайт можно не подключать (или оставить no-op).
- Капча/челлендж-стена бывают → `CaptchaError` переиспользуется.

**YouTube (Shorts):**
- Заливка — свой мульти-степ визард (детали видео → видимость → публикация), но паттерн «жди enabled, не visible; ждать успех до клика; без ретраев» тот же.
- Успех — «видео опубликовано»/ссылка на watch, ждём реальный сигнал.
- Файлы большие → remote-CDP потолок кусается сильнее; puppeteer-side-channel для заливки почти обязателен.
- В РФ YouTube троттлится — учитывай при выборе прокси и ожиданиях охвата.

Суть: **95% кода — общий каркас, 5% — `SELECTORS` + порядок шагов + гейты.** Именно ради этого мы держим постер framework-agnostic и не тащим в него БД/шедулер.
